# CactPkg - formats and protocols (v1)

The package manager for CactOS. A package source is either a directory on
disk/in the image (`/usr/lib/cactpkg/repo` by default) or a remote repository
reached over HTTPS; remote indexes and `.cpkg` artifacts are cached locally.
Plain `http://` is refused.

All multi-byte `.cpkg` fields are **little-endian** (i686).

---

## 1. Directory package (`pkg/<name>/`)

The source form of a package in the personal set. The directory contains:

```
pkg/<name>/
|-- manifest      # text manifest (required)
`-- payload/      # mirror of the installation root (bin/..., lib/..., sbin/...)
```

### Manifest

Lines of `key: value` or `key = value`. `#` is a comment, empty lines are
ignored. Order does not matter, duplicates are not allowed. An empty value
(for example `depends:`) means "field not set" and is skipped.

| Key           | Required | Example                  | Notes                            |
|---------------|----------|--------------------------|----------------------------------|
| `name`        | yes      | `hello`                  | `[A-Za-z0-9._-]+`                |
| `version`     | yes      | `1.0.0`                  | free-form string                 |
| `arch`        | yes      | `i686`                   | package architecture             |
| `description` | no       | `Hello, Cact!`           | single line                      |
| `depends`     | no       | `clibc, tools`           | comma-separated                  |

### Payload

The contents of `payload/` are copied as-is: `payload/bin/foo` ->
`<prefix>/bin/foo`. Permissions come from the real file permissions in the
directory (or from `mode` when a `.cpkg` is written by hand).

---

## 2. `.cpkg` artifact (v1)

The distributable package file. Generated from a directory package by the
host-side tool `tools/cpkg.py build`.

```
offset  size  field
------  ----  ---------------------------------------------
  0      4    magic "CKPK"
  4      1    version = 1
  5      1    reserved (0)
  6      2    flags (0)
  8      4    n_files   (number of file records)
 12      4    manifest_len
 16      4    manifest crc32 (0 = not computed)
 20      4    reserved
 24      4    reserved
 28      4    reserved
 32   manifest_len  manifest bytes (see section 1)
 ---  then n_files records follow consecutively ---
 each record:
  u16  name_len
  u16  mode      (chmod permissions)
  u32  size      (payload size)
  name_len bytes of name (path RELATIVE to the prefix, e.g. "bin/foo")
  size bytes of payload
```

v1 limits: names are at most 255 bytes, never absolute, and never contain
`..`. The whole file is read into memory (packages are small - up to ~1 MB).

---

## 3. Repository

A repository is a directory containing `.cpkg` files and a text `index`:

```
repo/
|-- index               # generated by: tools/cpkg.py index <repo>
|-- hello-2.0.0.cpkg    # hand-written packages (pkg/<name>/)
|-- cactpkg-2.0.0.cpkg
`-- ls-2.0.0.cpkg       # base-system packages: tools/cpkg.py sysrepo <userland> <repo>
```

### Remote repository

A `repo` entry may also be an `https://` URL. The same layout is served over
HTTPS; `cactpkg` appends `/index` and `/<file>` to the URL:

```
repo=https://packages.example.org/i686
```

- `cactpkg update` fetches `<url>/index` into the cache (see §4).
- `cactpkg install` fetches `<url>/<file>` on demand; a cached artifact is
  reused unless `--force` is given.
- **HTTPS is required.** A plain `http://` URL is refused, and a redirect that
  drops to `http://` is refused too — an unauthenticated index or artifact
  would be a trivial MITM. TLS 1.3 with certificate verification comes from
  libc (keys stay in the process); package files themselves are not signed yet
  (`.cpkg` has a `manifest crc32` field, currently not computed).
- Index entries carry only a plain file name (no `/`), so a remote index cannot
  escape the cache directory.

### index

Lines: `name<TAB>version<TAB>file<TAB>depends`. `depends` is comma-separated
or empty. `#` is a comment.

```
cactpkg	2.0.0	cactpkg-2.0.0.cpkg
hello	2.0.0	hello-2.0.0.cpkg
ls	2.0.0	ls-2.0.0.cpkg
```

One repository directory = one `index`. The config may list several
repositories (repeatable `repo` key).

## 4. Configuration `/etc/cactpkg.conf`

Same syntax as the manifest. If the file is missing, `cactpkg` writes a
documented default there on first run (without overwriting an existing file);
the built-in defaults apply if it cannot be created.

| Key       | Default                | Meaning                          |
|-----------|------------------------|----------------------------------|
| `prefix`  | `/usr/local`           | installation root of packages    |
| `db`      | `/var/lib/cactpkg`     | installed-packages db directory  |
| `cache`   | `/var/cache/cactpkg`   | download cache for remote repos  |
| `repo`    | `/usr/lib/cactpkg/repo`| repository source(s) - directory or http(s) URL (repeatable) |
| `arch`    | `i686`                 | accepted package architecture    |

All keys are overridden by command-line flags.

---

## 5. Installed-packages database (`<db>/installed/`)

One pair of files per installed package:

```
installed/<name>.manifest   # copy of the manifest from the .cpkg
installed/<name>.files      # absolute paths of installed files (one per line)
```

`<name>.manifest` marks the package as installed. The `<db>/installed`
directory is created on the first install.

---

## 6. `cactpkg` commands

| Command                      | Linux analog      | Action |
|------------------------------|-------------------|--------|
| `cactpkg update`             | `apt update`      | refresh the indexes of configured repositories (a remote index is downloaded) |
| `cactpkg install <pkg...>`   | `apt install`     | install by name from a repository (with dependencies) or by `.cpkg` path |
| `cactpkg remove <pkg...>`    | `apt remove`      | remove installed packages (with a dependents check) |
| `cactpkg list`               | `dpkg -l` / `pacman -Q` | list installed packages |
| `cactpkg search <pattern>`   | `apt search`      | search available repository packages |
| `cactpkg info <pkg>`         | `apt show` / `pacman -Si` | show package details (repository or installed) |
| `cactpkg files <pkg>`        | `dpkg -L`         | list files of an installed package |
| `cactpkg help`, `version`    | -                 | help / version |

Global flags: `-y`, `-f/--force`, `-R/--repo <dir|url>`,
`--prefix <dir>`, `--cache <dir>`, `-C/--conf <file>`, `-q`.
